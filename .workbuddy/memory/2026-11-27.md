# 2026-11-27

## 表格视图 + CSV 支持「平铺嵌套」（一层展开）

- 需求：表格里遇到对象/数组时，CSV 导出只能拿到 JSON 字符串（`{8} type: "疾病住院"…`），无法在 Excel 里用。
- 方案：新增 `flattenRow(obj, maxDepth)` + `isPrimitiveArray(v)`，在 `renderTable()` 里**先平铺再收集列**，表格视图与 CSV 导出共用同一份平铺数据。
- 规则：
  - 对象按层展开成 `incident.type` 这样的点号列，`maxDepth` 控制层数；
  - 基本类型数组用 `" | "` 合并成一格（`documents` → `住院病历首页 | 费用明细清单 | …`）；
  - 对象数组只在 `lvl+1 < maxDepth` 时按索引展开（`items[0].sku`），每个数组上限 20 个元素，防列爆炸。
- UI：表格工具栏加「平铺 [关闭/1 层/2 层/3 层]」下拉（默认 1 层），改动即重渲染并**重置排序**（列变了索引失效），值存 `localStorage['jv-flat']`。
- 数据结构变更：`state.tableRows` 保留**原始行**（点行号复制整行 JSON 用），新增 `state.tableView` 存同序的平铺行（渲染 + CSV + 单元格复制值都读它）。
- 排序改为对索引数组排序（`order.sort`）再映射回原始行，保证平铺值与原始行始终对齐。
- 工具栏拥挤问题：`.tiphint` 加 `flex:0 1 auto;min-width:0;overflow:hidden;text-overflow:ellipsis`；`tableInfo` 不再重复「· 平铺 N 层」（下拉里已有）；溢出提示缩到「↔ 可横滚」，默认提示「点格复制 · 点表头排序」。
- 验证（headless Chrome + `--dump-dom` 注入 `#__diag`）：claims 表 1 层 → 20 列，`incident.*` 7 列 + `review.*` 5 列 + documents 合并；关闭 → 回到 9 列原始行为；CSV 表头与平铺列一致，`csv_row1` 包含 `疾病住院`、`住院病历首页 | 费用明细清单 | …`。
- 坑：Chrome headless 传相对路径会被当 URL 解析（`ERR_NAME_NOT_RESOLVED`），必须用 `file:///C:/...` 且路径含空格要 `%20`。
- 布局实测 1000 / 1280 宽：`bar.scrollWidth === clientWidth`，hint 与 flatbox 无重叠，CSV 按钮完整可见。

## 追加：对象数组也按同规则展开（20:12）

- 原实现里对象数组要 `maxDepth ≥ 2` 才展开，与对象不一致。改为**同一判据** `lvl < maxDepth`：1 层时 `items:[{sku,qty}]` 直接出 `items[0].sku`、`items[0].qty`。
- 数组元素内部的嵌套对象不再"停在原地"，而是 `walk(el, sub, lvl+1)` 按剩余层数继续展开：2 层 → `items[0].detail.color`，3 层 → `items[0].detail.size.w`。
- 新增 `ARR_CAP = 20` 常量；单个对象数组超过 20 个元素时，额外输出 `name` 列存原始数组 JSON（不静默丢数据），前 20 个仍按索引展开。
- 边界确认：空数组走 `isPrimitiveArray`（空循环返回 true）→ 合并成空字符串；含 null 的基本类型数组 `[1,null,"s"]` → `"1 |  | s"`（沿用 Array.join 语义）。
- UI/CSV 实测（自制 orders 数据，1 层）：9 列 `orderNo|customer.name|customer.vip|items[0].sku|items[0].qty|items[1].sku|items[1].qty|tags|note`；关闭后回到 5 列；CSV 第 2 行缺失元素留空。
